    04 · Advanced SQL Features¶

    Exam Domain: T3 · Data Retrieval — query plans, SQL statistics, IRIS-specific SQL features, and SQL security

    Overview¶

    Ngoài các thao tác CRUD cơ bản, IRIS cung cấp nhiều tính năng SQL đặc trưng như cú pháp arrow -> để duyệt quan hệ object, hỗ trợ JSON trong SQL, và các pseudo-column hệ thống. Để tối ưu hiệu suất, IRIS cung cấp công cụ phân tích query plan (EXPLAIN) và cơ chế thu thập thống kê bảng (TuneTable). Bảo mật SQL được quản lý qua GRANT/REVOKE và views — tách biệt với hệ thống role của IRIS.

    IRIS-Specific SQL Features¶

    Implicit Join (Arrow Syntax ->)¶

    IRIS hỗ trợ duyệt quan hệ object trực tiếp trong SQL bằng toán tử ->. Thay vì viết JOIN tường minh, bạn có thể truy cập property của class được tham chiếu:

    -- Traverse object reference: Employee -> Manager (a Person object)
SELECT Name, Manager->Name AS ManagerName
FROM MyApp_Employee
WHERE Manager->Department = 'Engineering'
    • Cú pháp này chỉ hoạt động với các property là object reference (kiểu %Persistent)
    • IRIS tự động thực hiện join ngầm bằng cách theo dõi OID được lưu trong field
    • Có thể chain nhiều cấp: Manager->Department->Building->Address

    JSON in SQL¶

    IRIS hỗ trợ xây dựng và phân tích JSON trực tiếp trong câu SQL:

    -- Build a JSON object per row
SELECT JSON_OBJECT('name': Name, 'age': Age) AS PersonJSON
FROM MyApp_Person
WHERE Age > 25

-- Build a JSON array
SELECT JSON_ARRAY(Name, Age, Email) AS PersonArray
FROM MyApp_Person

-- JSON_TABLE: shred a JSON string into relational rows (advanced)
SELECT jt.*
FROM MyApp_Config,
     JSON_TABLE(ConfigData, '$[*]' COLUMNS (key VARCHAR(50) PATH '$.key')) AS jt

    Pseudo-column %OBJECT trả về toàn bộ row như một registered object, dùng được trong Embedded Python hoặc ObjectScript.

    System Pseudo-Columns¶

    Pseudo-column Ý nghĩa
    %ID Object ID của row — tương đương RowID, luôn có mặt trong mọi bảng
    %TABLENAME Tên bảng thực sự — hữu ích trong polymorphic query
    %CLASSNAME Tên class cụ thể của object (khi query trên class cha) 
    -- Always available — no need to define an ID column manually
SELECT %ID, Name, Age FROM MyApp_Person WHERE %ID = 42

    Date/Time Functions¶

    IRIS hỗ trợ các hàm date/time chuẩn SQL:

    SELECT CURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP

-- Date arithmetic
SELECT DATEADD('day', 30, BirthDate) AS ExpireDate FROM MyApp_Person
SELECT DATEDIFF('year', BirthDate, CURRENT_DATE) AS Age FROM MyApp_Person
SELECT DATEPART('month', CreatedAt) AS Month FROM MyApp_Person

    Query Plans¶

    EXPLAIN¶

    EXPLAIN trả về mô tả văn bản về cách IRIS thực thi một câu SQL — không chạy query thật:

    EXPLAIN SELECT Name, Age FROM MyApp_Person WHERE Age > 25

    Output cho biết: - Index nào được sử dụng (hoặc không) - Chiến lược join - Số row ước tính

    Show Plan trong Management Portal¶

    Vào System → SQL → Execute Query, tick chọn "Show Plan" trước khi chạy query để xem sơ đồ query plan dạng đồ họa. Đây là cách trực quan nhất để kiểm tra hiệu suất.

    Đọc Query Plan¶

    Thông báo trong plan Ý nghĩa
    Read master map Full table scan — không có index được dùng
    Read index Index được sử dụng — hiệu suất tốt
    Temp storage Kết quả trung gian lưu vào temp global — cần lưu ý bộ nhớ
    Bitmap index Rất hiệu quả cho cột có cardinality thấp (ít giá trị phân biệt)

    Lấy Query Plan từ ObjectScript¶

    SET stmt = ##class(%SQL.Statement).%New()
DO stmt.%Prepare("SELECT Name FROM MyApp_Person WHERE Age > ?")
WRITE stmt.%GetImplementationClass().GetPlan(), !

    SQL Statistics & Statement Index¶

    SQL Statement Index¶

    IRIS tự động thu thập thống kê về các câu SQL đã thực thi: - Số lần thực thi (execution count) - Thời gian trung bình / tổng thời gian - Số row trả về

    Xem tại: Management Portal → System → SQL → SQL Statement Index (hoặc Cached Queries). Đây là công cụ chính để tìm slow query và query được gọi nhiều nhất.

    TuneTable — Thu thập thống kê bảng¶

    Query optimizer của IRIS dựa trên thống kê (row count, selectivity theo field/index) để chọn plan tối ưu. Nếu thống kê cũ hoặc thiếu, optimizer có thể chọn sai plan.

    // Gather statistics for a table (1 = verbose output)
DO ##class(%SYSTEM.SQL).TuneTable("MyApp.Person", 1)

    Hoặc từ SQL:

    TUNE TABLE MyApp_Person

    Nên chạy TuneTable sau mỗi lần load dữ liệu lớn (bulk import) hoặc khi thấy query đột ngột chậm.

    Import thống kê từ môi trường production để đảm bảo optimizer trong dev có thể mô phỏng hành vi thực tế — đặc biệt quan trọng khi dev database có ít data hơn production.

    ExtentSize¶

    EXTENTSIZE là gợi ý số row dự kiến cho optimizer — được dùng khi chưa có thống kê thực tế:

    // Read current ExtentSize
WRITE ##class(MyApp.Person).%GetParameter("EXTENTSIZE"), !

    Hoặc khai báo trong class:

    Class MyApp.Person Extends %Persistent
{
    Parameter EXTENTSIZE = 50000;
    // ...
}

    SQL Security¶

    GRANT và REVOKE¶

    -- Grant SELECT on a table to a user
GRANT SELECT ON MyApp_Person TO appuser

-- Grant multiple privileges at once
GRANT SELECT, INSERT, UPDATE ON MyApp_Person TO appuser

-- Grant to a role
GRANT SELECT ON MyApp_Person TO %DB_USER

-- Revoke a privilege
REVOKE DELETE ON MyApp_Person FROM appuser

    Các privilege SQL bao gồm: SELECT, INSERT, UPDATE, DELETE, REFERENCES, EXECUTE (cho stored procedure).

    Table-level vs Column-level Security¶

    IRIS không hỗ trợ column-level privilege trực tiếp. Thay vào đó, dùng View để giới hạn cột người dùng được phép truy cập:

    -- Expose only safe columns via a view
CREATE VIEW MyApp_PersonPublic AS
SELECT Name, Email FROM MyApp_Person

-- Grant access to the view, not the base table
GRANT SELECT ON MyApp_PersonPublic TO publicuser

    Row-Level Security với Views¶

    -- Filter rows based on the current SQL user
CREATE VIEW MyApp_MyPersonView AS
SELECT * FROM MyApp_Person
WHERE OwnerUsername = CURRENT_USER

    Cấp quyền trên view thay vì bảng gốc — người dùng chỉ thấy đúng rows của họ.

    SQL Injection Prevention¶

    Không bao giờ nối chuỗi input của user vào SQL string. Luôn dùng parameterized query:

    // WRONG - SQL injection risk
SET sql = "SELECT * FROM MyApp_Person WHERE Name = '" _ userInput _ "'"

// CORRECT - use ? placeholder in Dynamic SQL
SET stmt = ##class(%SQL.Statement).%New()
DO stmt.%Prepare("SELECT * FROM MyApp_Person WHERE Name = ?")
SET rs = stmt.%Execute(userInput)

// CORRECT - use :varName in Embedded SQL
&sql(SELECT Name INTO :name FROM MyApp_Person WHERE %ID = :targetId)

    Key Points¶

    • ✅ -> arrow syntax = implicit join via object reference (IRIS-specific, very useful)
    • ✅ %ID = system-managed row ID column; always available in every table
    • ✅ TuneTable gathers statistics for the query optimizer — run after bulk data loads
    • ✅ SQL Statement Index shows execution history and performance metrics for all queries
    • ⚠️ Missing table statistics → optimizer picks wrong plan → slow queries
    • ⚠️ Full table scan ("Read master map") on large tables = performance problem
    • ⚠️ GRANT/REVOKE SQL privileges are separate from IRIS security roles — both apply
    • 💡 Use EXPLAIN or Show Plan to verify an index is being used before deploying a query
    • 💡 Arrow syntax -> is much cleaner than explicit JOIN for navigating IRIS object relationships

    🖥️ Terminal Snippets¶

    // --- Tune table statistics ---
DO ##class(%SYSTEM.SQL).TuneTable("MyApp.Person", 1)  // 1 = verbose output

// --- Check EXPLAIN plan ---
SET rs = ##class(%SQL.Statement).%ExecDirect(,"EXPLAIN SELECT Name FROM MyApp_Person WHERE Age > 25")
WHILE rs.%Next() { WRITE rs.%GetData(1), ! }

// --- Grant privilege (run as admin) ---
SET sc = ##class(%SYSTEM.SQL.Security).GrantObjectPrivilege("SELECT", "MyApp_Person", "sqlusr")

// --- View SQL Statement Index from ObjectScript ---
SET rs = ##class(%SQL.Statement).%ExecDirect(,"SELECT Statement, RowCount, TotalTime FROM %SYS_CACHEQUERY.Statement ORDER BY TotalTime DESC")
WHILE rs.%Next() { WRITE rs.%Get("Statement"), " -- ", rs.%Get("TotalTime"), ! }

// --- Read ExtentSize hint ---
WRITE ##class(MyApp.Person).%GetParameter("EXTENTSIZE"), !

// --- Get plan from prepared statement ---
SET stmt = ##class(%SQL.Statement).%New()
DO stmt.%Prepare("SELECT Name FROM MyApp_Person WHERE Age > ?")
WRITE stmt.%GetImplementationClass().GetPlan(), !
