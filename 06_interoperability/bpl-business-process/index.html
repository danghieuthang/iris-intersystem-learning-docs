    BPL Business Process¶

    Exam Domain: T1 · Architecture — thiết kế Business Process bằng BPL graphical designer trong Management Portal, không cần viết ObjectScript

    Overview¶

    BPL (Business Process Language) là cách tạo Business Process bằng giao diện đồ họa Business Process Designer trong Management Portal — kéo-thả activities vào canvas, IRIS tự sinh code ObjectScript từ diagram XML. Phù hợp cho flow đơn giản, sequential, dễ visualize và dễ đọc với non-developer.

    [Business Service]
      ↓ Ens.Request
[BPL Business Process]  ← diagram gồm: assign / if / call / sync / foreach
      ↓ Ens.Request (đã xử lý)
[Business Operation]

    BPL class tự động Extends Ens.BusinessProcessBPL. Không cần viết code ObjectScript thủ công.

    Business Process Designer¶

    Tạo BPL mới¶

    1. Management Portal → Interoperability → chọn Namespace
    2. Build → Business Process
    3. Đặt tên class (e.g., MyApp.BP.OrderFlow) → OK
    4. Business Process Designer mở ra — bắt đầu kéo activities vào canvas

    ⚠️ Đừng edit file .cls của BPL trực tiếp — luôn dùng Designer vì file được generate từ XML diagram.

    BPL Activities¶

    Assign¶

    Gán giá trị cho context property hoặc biến.

    Activity: assign
Property: context.Status
Value:     "Approved"
Action:    set        ← set / append / clear

    Dùng để: copy field từ request vào context, set giá trị mặc định, transform đơn giản.

    If / Else¶

    Rẽ nhánh dựa trên điều kiện.

    condition: request.Priority = "urgent"
  → TRUE branch:  gọi BO.ExpressProcessor
  → FALSE branch: gọi BO.StandardProcessor
    • Condition viết bằng ObjectScript expression (trả về 1/0)
    • Nest được nhiều cấp if lồng nhau

    Call¶

    Gửi message đến một Business Operation hoặc Business Process khác.

    Property Ý nghĩa
    Target Config name của BO/BP đích (trong Production)
    Request class Class của message gửi đi
    Response class Class của response nhận về
    Async Checked = không chờ; Unchecked = block cho đến khi có response

    Response lưu tự động vào callrequest / callresponse context variables.

    Sync¶

    Chờ tất cả các async call trước đó hoàn thành trước khi tiếp tục.

    [call async → BO.Logger]
[call async → BO.Auditor]
[sync]              ← chờ cả 2 xong rồi mới tiếp tục
[assign context.Done = 1]

    Sync chỉ có tác dụng với các call async — nếu dùng với sync call thì không cần thiết.

    For Each (Loop)¶

    Lặp qua một list hoặc array trong context.

    Activity:   foreach
Key:        context.CurrentItem    ← biến giữ từng phần tử
Collection: context.ItemList       ← collection cần lặp

    Bên trong vòng lặp: đặt các activities xử lý context.CurrentItem.

    Context Properties¶

    Context là object trung gian lưu trạng thái của BPL suốt quá trình xử lý — tương tự instance variables trong ObjectScript.

    Định nghĩa context properties¶

    Trong Designer: tab Context → thêm property:

    Field Ví dụ
    Name OrderTotal
    Type %Numeric
    Initial Value 0

    Truy cập trong activities¶

    context.OrderTotal          ← đọc/ghi trong Assign, If condition
request.FieldName           ← input message (read-only)
response.FieldName          ← output message (write để set response)

    Context sống trong suốt vòng đời của BPL instance — kể cả khi BP bị suspend rồi resume (stateful).

    Thêm BPL vào Production¶

    1. Management Portal → Interoperability → Configure → Production
    2. Click + bên cột Processes
    3. Chọn class BPL vừa tạo → Apply
    4. Cấu hình cơ bản:
    Setting Ý nghĩa
    Config Name Tên dùng làm target trong SendRequestSync/Async từ BS
    Pool Size Số jobs chạy song song (mặc định 1)
    Log Trace Events Bật để xem detail trong Visual Trace
    Enabled Bật/tắt component

    Test BPL trên Production Configuration Page¶

    1. Chọn BP component trong Production → tab Actions
    2. Click Test → chọn Request Message Class
    3. Điền giá trị fields của request → Invoke Testing Service
    4. Xem kết quả trong Visual Trace (tab Messages → click message → Show Trace)

    Visual Trace hiển thị từng activity đã execute, giá trị context tại mỗi bước — rất hữu ích để debug BPL.

    Key Points¶

    • ✅ BPL class extends Ens.BusinessProcessBPL — IRIS tự generate code từ XML diagram
    • ✅ Context là stateful — tồn tại xuyên suốt vòng đời BP, kể cả khi suspend/resume
    • ✅ call activity có thể sync (block) hoặc async (fire-and-forget) — cấu hình qua checkbox
    • ✅ sync activity dùng để chờ nhiều async call cùng lúc trước khi tiếp tục
    • ⚠️ Đừng edit file .cls của BPL trực tiếp — luôn dùng Business Process Designer
    • ⚠️ Target trong call activity phải khớp config name trong Production, không phải class name
    • 💡 Dùng Visual Trace để xem từng activity đã execute và giá trị context tại mỗi bước
    • 💡 BPL phù hợp cho flow đơn giản — dùng ObjectScript class khi cần logic phức tạp, điều kiện động
