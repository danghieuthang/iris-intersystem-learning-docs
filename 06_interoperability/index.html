    06 · Interoperability / Productions¶

    Exam Domain: T1 · Architecture — hiểu mô hình Production (BS → BP → BO) và cách các component giao tiếp qua Messages

    Overview¶

    Interoperability là framework tích hợp của IRIS, cho phép kết nối hệ thống bên ngoài (file, HTTP, HL7, database...) thông qua mô hình Production. Một Production là container chạy các component giao tiếp với nhau qua Message Queue — đảm bảo reliable delivery, retry, và audit log đầy đủ.

    [External System]
      ↓
[Business Service]   ← nhận data từ ngoài (inbound adapter)
      ↓  Message
[Business Process]   ← routing, transformation, orchestration
      ↓  Message
[Business Operation] ← gửi data ra ngoài (outbound adapter)
      ↓
[External System]

    The Three Components¶

    Component Base Class Vai trò Method chính
    Business Service Ens.BusinessService Nhận data từ ngoài vào OnProcessInput()
    Business Process Ens.BusinessProcess Xử lý, routing, transform OnRequest()
    Business Operation Ens.BusinessOperation Gửi data ra ngoài OnMessage()

    Business Service¶

    Class MyApp.BS.FileReader Extends Ens.BusinessService
{

Parameter ADAPTER = "EnsLib.File.InboundAdapter";

Method OnProcessInput(pInput As %Stream.Object, pOutput As %RegisteredObject) As %Status
{
    SET msg = ##class(MyApp.Msg.FileData).%New()
    SET msg.Content = pInput.Read()
    RETURN ..SendRequestSync("MyApp.BP.Router", msg, .response)
}

}

    Business Process¶

    Class MyApp.BP.Router Extends Ens.BusinessProcess
{

Method OnRequest(pRequest As MyApp.Msg.FileData, Output pResponse As %RegisteredObject) As %Status
{
    IF pRequest.Content [ "urgent" {
        RETURN ..SendRequestSync("MyApp.BO.EmailSender", pRequest, .pResponse)
    }
    RETURN ..SendRequestSync("MyApp.BO.DatabaseWriter", pRequest, .pResponse)
}

}

    Business Operation¶

    Class MyApp.BO.DatabaseWriter Extends Ens.BusinessOperation
{

Method OnMessage(pRequest As MyApp.Msg.FileData, Output pResponse As %RegisteredObject) As %Status
{
    SET record = ##class(MyApp.Data.FileRecord).%New()
    SET record.Content = pRequest.Content
    RETURN record.%Save()
}

}

    Message Classes¶

    Mọi dữ liệu trao đổi giữa các component phải được đóng gói trong Message class (extend Ens.Request hoặc Ens.Response). Message được persist vào database — đây là cơ sở để retry và audit.

    Class MyApp.Msg.FileData Extends Ens.Request
{
    Property Content As %String(MAXLEN = 32000);
    Property FileName As %String;
    Property Priority As %String [ InitialExpression = "normal" ];
}

    Sync vs Async¶

    Method Hành vi Khi dùng
    ..SendRequestSync(target, req, .resp) Chờ response Cần kết quả để xử lý tiếp
    ..SendRequestAsync(target, req) Fire and forget Không cần kết quả ngay

    Custom Components — Deep Dive¶

    Mỗi component có conventions riêng khi coding. Xem chi tiết:

    • 📄 Custom Business Service — nhận data từ ngoài vào
    • 📄 Custom Business Process — routing, transform, orchestration
    • 📄 Custom Business Operation — gửi data ra ngoài

    Key Points¶

    • ✅ Production là container — start/stop toàn bộ component cùng lúc
    • ✅ Mọi component giao tiếp qua Message (không call trực tiếp)
    • ✅ Message được lưu vào DB — hỗ trợ retry tự động khi lỗi
    • ⚠️ Component name trong SendRequestSync phải khớp chính xác với config name trong Production, không phải class name
    • ⚠️ Ens.Request và Ens.Response là hai base class khác nhau — dùng đúng loại
    • 💡 Dùng Event Log trong Management Portal → Interoperability để debug message flow

    🖥️ Terminal Snippets¶

    // --- Start/Stop Production ---
DO ##class(Ens.Director).StartProduction("MyApp.Production")
DO ##class(Ens.Director).StopProduction()

// --- Kiểm tra Production đang chạy ---
WRITE ##class(Ens.Director).IsProductionRunning(), !

// --- Gửi test message thủ công ---
SET msg = ##class(MyApp.Msg.FileData).%New()
SET msg.Content = "test content"
SET msg.FileName = "test.txt"
SET sc = ##class(Ens.Director).CreateBusinessService("MyApp.BS.FileReader", .bs)
