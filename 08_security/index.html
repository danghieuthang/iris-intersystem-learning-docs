    08 · Security & Namespaces¶

    Exam Domain: T4 · Code — hiểu mô hình phân quyền của IRIS (User/Role/Resource/Privilege), namespaces, và kiểm tra permission trong code

    Overview¶

    IRIS dùng mô hình bảo mật phân lớp: User được gán Role, Role chứa tập hợp Privilege trên Resource. Namespace là không gian làm việc logic — mỗi namespace ánh xạ đến databases riêng cho code và data. Mọi cấu hình bảo mật được quản lý qua Management Portal → Security.

    Namespaces¶

    Namespace là "môi trường làm việc" — code compile trong namespace nào thì chạy trong namespace đó. Globals có thể được share hoặc private giữa các namespaces thông qua Global Mapping.

    IRIS Instance
├── %SYS        ← system namespace (cẩn thận)
├── USER        ← default development namespace
└── MYAPP       ← custom namespace cho application
    ├── Database: MYAPP_DATA  (globals)
    └── Database: MYAPP_CODE  (classes, routines)

    // Xem namespace hiện tại
WRITE $NAMESPACE, !

// Chuyển namespace
ZNSPACE "USER"
// hoặc
SET $NAMESPACE = "MYAPP"

    Security Model¶

    Khái niệm Mô tả Ví dụ
    User Tài khoản đăng nhập _SYSTEM, Admin, appuser
    Role Tập hợp privileges %DB_USER, %Manager
    Resource Thứ được bảo vệ Database, Service, Application
    Privilege Quyền cụ thể trên resource READ, WRITE, USE

    Chuỗi quan hệ: User → Role(s) → Privilege(s) → Resource(s)

    Authentication Modes¶

    Mode Mô tả Khi dùng
    Password Username/password IRIS Phổ biến nhất
    Operating System Dùng OS user Single sign-on nội bộ
    Kerberos Enterprise SSO Active Directory
    Delegated Custom auth class Auth tích hợp với hệ thống khác
    Unauthenticated Không cần login Public endpoint (REST API public)

    Permission Check in Code¶

    // Kiểm tra user có privilege trên resource không
IF $SYSTEM.Security.Check("%DB_USER", "USE") {
    // có quyền
}

// Lấy thông tin user hiện tại
WRITE $USERNAME, !
WRITE $ROLES, !   // danh sách roles, phân cách bằng dấu phẩy

// Kiểm tra role cụ thể
IF ($ROLES [ "%Manager") {
    // user có role %Manager
}

    Key Points¶

    • ✅ Default namespaces: USER (dev), %SYS (system), SAMPLES
    • ✅ Principle of least privilege — chỉ cấp quyền tối thiểu cần thiết
    • ⚠️ %SYS là namespace system — thao tác sai có thể ảnh hưởng toàn bộ instance
    • ⚠️ Unauthenticated mode không có nghĩa là không an toàn — vẫn cần kiểm soát qua Resource
    • 💡 Bật Audit Log (Management Portal → Security → Auditing) để theo dõi ai làm gì và khi nào

    🖥️ Terminal Snippets¶

    // --- Xem namespace và user hiện tại ---
WRITE "Namespace: ", $NAMESPACE, !
WRITE "User: ", $USERNAME, !
WRITE "Roles: ", $ROLES, !

// --- Chuyển namespace ---
ZNSPACE "USER"

// --- Kiểm tra privilege ---
WRITE $SYSTEM.Security.Check("%DB_USER", "USE"), !

// --- List tất cả namespaces (chạy trong %SYS) ---
ZNSPACE "%SYS"
DO ##class(Config.Namespaces).List(.list)
SET ns = "" FOR { SET ns = $ORDER(list(ns)) QUIT:ns=""  WRITE ns, ! }
