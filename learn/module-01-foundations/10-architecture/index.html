    10 · Architecture & Database Design¶

    Exam Domain: T1 · Architecture — namespaces, databases, global mappings, mirroring, scalability

    Overview¶

    InterSystems IRIS có kiến trúc phân tầng: một instance IRIS chứa nhiều namespace (không gian logic), mỗi namespace ánh xạ tới một hoặc nhiều database vật lý lưu trữ dữ liệu thực sự trên đĩa. Hiểu rõ mối quan hệ này là nền tảng để thiết kế hệ thống có khả năng mở rộng, bảo trì và triển khai CI/CD hiệu quả.

    Namespaces & Databases¶

    Namespace là điểm truy cập logic — nơi bạn viết code và truy vấn dữ liệu. Database là file vật lý (.IRIS.DAT) lưu trữ globals và routines thực sự trên đĩa. Một namespace luôn có: - Default globals database: nơi lưu globals mặc định - Default code/routines database: nơi lưu compiled classes và routines - Optional mappings: ánh xạ bổ sung tới databases khác

    Namespace %SYS là namespace hệ thống — chứa cấu hình, security, và management APIs. Không dùng %SYS cho application code.

    IRIS Instance
├── %SYS (system — configuration, security)
├── USER (default dev namespace)
└── MYAPP (application namespace)
    ├── Globals DB: MYAPP_DATA.IRIS.DAT
    └── Code DB:    MYAPP_CODE.IRIS.DAT

    Tạo namespace mới: Management Portal → System Administration → Namespaces → Create New Namespace.

    Global Mappings¶

    Global mappings cho phép một global từ database khác "xuất hiện" trong namespace hiện tại, như thể nó thuộc namespace đó.

    Loại mapping Mục đích
    Global mapping Map một hoặc nhiều globals tới database khác
    Package mapping Map toàn bộ một class package tới code database khác
    Routine mapping Map specific routines tới database khác
    Subscript mapping Map các subscript khác nhau của cùng một global tới các databases khác nhau

    Ví dụ use case — Subscript mapping:
    Phân vùng dữ liệu trên nhiều đĩa: ^Orders(2023,*) → ARCHIVE_DB, ^Orders(2024,*) → CURRENT_DB. Hữu ích khi dữ liệu quá lớn cho một database.

    Ví dụ use case — Global mapping:
    Chia sẻ ^SharedConfig giữa nhiều application namespaces mà không cần copy dữ liệu.

    // Check which database a global maps to (run in %SYS)
// Note: global name does NOT include the ^ prefix
SET sc = ##class(Config.MapGlobals).Get("MYAPP", "SharedData", .props)
ZWRITE props

    Mirroring (High Availability)¶

    Mirroring là cơ chế High Availability (HA) của IRIS: hai hoặc nhiều IRIS instances tạo thành một mirror set.

    Thành phần Vai trò
    Primary member Instance đang phục vụ requests (read/write)
    Backup/Failover member Instance standby, nhận journal từ primary
    Async member Read-only copy, dùng cho disaster recovery, có thể ở địa điểm khác
    Arbiter Lightweight process giải quyết tie-breaking khi mất kết nối
    Virtual IP IP address tự động chuyển sang backup khi failover

    Cơ chế: IRIS dùng journal-based logical replication — mọi thay đổi trên primary được ghi vào journal và replicate sang backup member theo thời gian thực.

    Automatic failover: Khi primary down, backup tự động promote lên primary và Virtual IP chuyển sang backup server — ứng dụng không cần thay đổi connection string nếu dùng Virtual IP.

    ⚠️ Luôn dùng Virtual IP (mirror IP) trong connection strings, không dùng IP vật lý của server cụ thể.

    Sharding (Horizontal Scalability)¶

    Sharding chia nhỏ (partition) dữ liệu trên nhiều IRIS nodes trong một sharded cluster. Đây là giải pháp scale-out — tăng capacity bằng cách thêm nodes.

    • Dùng cho dataset rất lớn hoặc workload ingestion cao
    • Query performance gần tuyến tính khi tăng số nodes
    • Khác với Mirroring: Mirroring = HA (dữ liệu giống nhau ở cả 2 nodes), Sharding = Scalability (mỗi node giữ 1 phần dữ liệu)
    Mirroring Sharding
    Mục đích High Availability Horizontal Scale-out
    Số nodes 2 (+ async) N nodes
    Dữ liệu Replicated (full copy) Partitioned (partial)
    Failover Tự động Không (cluster node failure cần xử lý riêng)

    Configuration Settings for Scale¶

    Các tham số cấu hình ảnh hưởng trực tiếp tới performance và stability:

    Setting Ý nghĩa Vị trí
    Global Buffers Memory cache cho database blocks; lớn hơn → ít đọc đĩa hơn Memory and Startup
    Routine Buffers Cache cho compiled code/routines Memory and Startup
    gmheap Generic memory heap (lock table, shared memory) Memory and Startup
    Lock Table size Số locks đồng thời tối đa; tăng nếu gặp "lock table full" Memory and Startup
    $ZSTORAGE Per-process memory limit (mặc định 256 MB; tối đa phụ thuộc OS, ~2^41 bytes trên 64-bit) Per-process setting

    Tất cả cấu hình qua: Management Portal → System Administration → Configuration → Memory and Startup,
    hoặc trực tiếp trong file iris.cpf.

    // Check per-process memory limit
WRITE $ZSTORAGE, !

// Check lock table usage
WRITE ##class(%SYSTEM.Lock).GetLockTableUsed(), !

    CPF File (Configuration Parameter File)¶

    iris.cpf là file cấu hình chính của một IRIS instance — "source of truth" cho toàn bộ cấu hình instance.

    CPF kiểm soát: - Danh sách databases và namespaces - Global/package/routine mappings - Memory settings (buffers, gmheap) - Startup settings và journal configuration

    Dùng trong CI/CD với lệnh iris merge:

    CPF Merge được thực hiện qua command-line tool (không phải ObjectScript API):

    # Apply config changes from a partial CPF merge file (Windows & Linux)
iris merge IRIS "D:\configs\myapp-delta.cpf"

    Merge file là một partial CPF chỉ chứa các sections cần thay đổi, ví dụ: 

    [config]
globals=0,0,800,0,0,0
gmheap=256000

    ⚠️ Không edit iris.cpf bằng tay trên hệ thống đang chạy. Dùng Management Portal, Config API, hoặc iris merge.

    IRIS Upgrade Implications¶

    Khi nâng cấp IRIS lên version mới:

    1. Database conversion: databases có thể cần convert sang format mới — quá trình này không thể reverse
    2. Deprecated features: một số APIs hoặc globals syntax có thể bị deprecated — kiểm tra release notes
    3. Test trước: luôn test trong staging environment trước khi upgrade production
    4. Mirror upgrade procedure:
    5. Upgrade backup member trước
    6. Failover (promote backup thành primary)
    7. Upgrade original primary (giờ là backup)
    8. Failover lại về original primary nếu cần

    IRIS BI / Analytics Trade-offs¶

    IRIS BI (DeepSee) là OLAP-style analytics engine tích hợp sẵn trong IRIS, cho phép query kiểu aggregation nhanh trên dữ liệu IRIS.

    IRIS BI (DeepSee) External BI (JDBC/ODBC)
    Latency Thấp (cubes được pre-built) Phụ thuộc network và tool
    Storage Tốn thêm cho cube storage Không tốn IRIS storage
    Real-time Gần real-time với scheduling Theo batch/pull
    Use case Reporting trong IRIS stack Tích hợp với Tableau, Power BI, v.v.

    Key Points¶

    • ✅ Namespace = logical container (access point); Database = physical file (.IRIS.DAT on disk)
    • ✅ Một namespace có thể dùng globals từ nhiều databases vật lý khác nhau thông qua mappings
    • ✅ Mirroring = High Availability (2 nodes, full data copy); Sharding = Scalability (N nodes, partitioned data)
    • ✅ CPF file (iris.cpf) là source of truth cho cấu hình instance — key cho CI/CD automation
    • ⚠️ %SYS namespace chứa cấu hình hệ thống — chỉnh sửa sai có thể làm hỏng toàn bộ instance
    • ⚠️ Dùng Virtual IP (mirror IP) trong connection strings, không dùng IP vật lý của từng server
    • ⚠️ Global Buffers quá nhỏ là nguyên nhân phổ biến nhất gây performance bottleneck
    • 💡 Tách code database khỏi data database giúp backup, restore, và maintain dễ hơn
    • 💡 Dùng lệnh iris merge IRIS merge-file.cpf để apply cấu hình tự động trong CI/CD pipeline

    🖥️ Terminal Snippets¶

    // --- Check current namespace ---
WRITE $NAMESPACE, !

// --- Switch namespace ---
ZNSPACE "MYAPP"

// --- Switch to system namespace ---
ZNSPACE "%SYS"

// --- List all databases (must be in %SYS) ---
ZNSPACE "%SYS"
DO ##class(SYS.Database).%GetAll(.dbList)
SET db = ""
FOR {
    SET db = $ORDER(dbList(db))
    QUIT:db=""
    WRITE db, !
}

// --- Check mirror status (accessible from any namespace) ---
WRITE $SYSTEM.Mirror.GetMemberStatus(), !
WRITE $SYSTEM.Mirror.IsPrimary(), !
WRITE $SYSTEM.Mirror.GetMemberType(), !

// --- Check lock table usage ---
WRITE ##class(%SYSTEM.Lock).GetLockTableUsed(), !

// --- Check per-process memory limit ---
WRITE $ZSTORAGE, !

// --- Apply CPF merge for CI/CD (command-line, not ObjectScript) ---
// Run from OS shell: iris merge IRIS "D:\configs\myapp-delta.cpf"
