    Object Lifecycle¶

    Exam Domain: T1 · Architecture — %New, %OpenId, %Save, callbacks, swizzling, và quyết định vòng đời object

    Overview¶

    Khi làm việc với object trong IRIS, phần dễ bỏ sót không phải cú pháp tạo class mà là vòng đời của instance: object được tạo khi nào, vào memory ra sao, save theo transaction như thế nào, và reference object được load lúc nào. Exam thường hỏi vào %New, %OpenId, %Save, callback flow, và swizzling.

    Create, Open, and Check Existence¶

    Action Method Use
    tạo object mới trong memory %New() object chưa tồn tại trên disk
    mở object đã lưu %OpenId(id) load theo ID
    kiểm tra tồn tại %ExistsId(id) check nhanh trước khi open 
    // --- Create a new object in memory ---
SET person = ##class(MyApp.Person).%New()
SET person.Name = "Alice"

// --- Open an existing object ---
SET person = ##class(MyApp.Person).%OpenId(1)

// --- Check existence ---
WRITE ##class(MyApp.Person).%ExistsId(1), !

    ⚠️ %New() chỉ tạo object trong memory. Chỉ sau %Save() object mới được persist.

    %Save() and SaveSet¶

    SET person = ##class(MyApp.Person).%New()
SET person.Name = "Alice"
SET sc = person.%Save()
IF $$$ISERR(sc) {
    WRITE $SYSTEM.Status.GetErrorText(sc), !
}

    %Save() không chỉ save object hiện tại. IRIS trước hết dựng một SaveSet gồm các object reachable từ object đang save:

    • embedded objects
    • collections
    • streams
    • referenced objects
    • relationships liên quan

    Why This Matters¶

    • save order dependencies được resolve tự động
    • toàn bộ operation chạy như một transaction
    • nếu một object fail validation/save, toàn bộ save rollback

    ✅ Đây là điểm rất quan trọng: %Save() của object graph có transactional behavior, không chỉ save từng mảnh rời rạc.

    Save-related Callbacks¶

    Trong flow save, IRIS có thể gọi nhiều callback quan trọng:

    Callback Khi chạy
    %OnAddToSaveSet() khi object được thêm vào SaveSet
    %OnValidateObject() trước khi save, trong bước validation
    %OnBeforeSave() ngay trước khi serialize/save
    %OnAfterSave() ngay sau khi save object
    %OnSaveFinally() sau khi transaction đã finalize
    %OnRollBack() khi save transaction rollback sau khi object đã được serialize

    Design Guidance¶

    • dùng callback cho business rule liên quan lifecycle
    • không nhồi logic ngẫu nhiên vào %OnBeforeSave() nếu không thật sự thuộc persistence lifecycle
    • callback fail -> %Save() fail -> transaction rollback

    Opening Objects and Reloading¶

    SET person = ##class(MyApp.Person).%OpenId(10)
IF person = "" {
    WRITE "Not found", !
    QUIT
}

    %OpenId() trả về:

    • một OREF nếu open thành công
    • "" nếu không open được hoặc không tìm thấy object

    %Reload()¶

    Nếu object đã được open trong process và bạn muốn ép reload lại từ disk:

    DO person.%Reload()

    Điều này đặc biệt hữu ích khi:

    • đã sửa object trong memory nhưng chưa save
    • muốn bỏ local changes và quay lại persisted state

    Same Process vs Different Process¶

    Trong cùng một IRIS process, gọi %OpenId() nhiều lần cho cùng class + cùng ID sẽ trả về cùng object instance trong memory.

    Điều đó có nghĩa:

    • sửa qua biến A thì biến B cùng trỏ object đó cũng nhìn thấy thay đổi
    • nhưng process khác (ví dụ chạy bằng JOB) sẽ load instance riêng

    Why This Matters¶

    Đây là lý do behavior "mở lại mà vẫn thấy local change chưa save" có thể xảy ra trong cùng process.

    Concurrency in %OpenId()¶

    Chữ ký %OpenId() có tham số concurrency:

    SET person = ##class(MyApp.Person).%OpenId(6,0,.sc)

    Ý chính cần nhớ:

    • concurrency argument quyết định locking/concurrency level khi open object
    • nếu IRIS không acquire được lock cần thiết, %OpenId() có thể fail
    • reopen với concurrency khác có thể raise/lower current concurrency setting

    ⚠️ Đây là concurrency ở object opening level, không thay thế hoàn toàn cho design locking/transaction tổng thể.

    Swizzling (Lazy Loading)¶

    Nếu object đã mở có property tham chiếu tới object persistent khác, object được tham chiếu sẽ được tự động open khi bạn chạm tới nó. Đây là swizzling.

    SET emp = ##class(Sample.Employee).%OpenId(101)
WRITE emp.Company.Name, !

    Trong ví dụ này:

    • emp được open trước
    • Company object chỉ được load khi code truy cập emp.Company.Name

    Why Swizzling Matters¶

    Benefit Trade-off
    giảm load ban đầu có thể tạo thêm I/O bất ngờ khi traverse object graph
    code tự nhiên hơn dễ quên chi phí lazy loading
    tốt cho relationship navigation cần cẩn thận trong loop lớn

    Swizzled object được open với default concurrency value của class thành viên đó, không nhất thiết dùng concurrency của object gốc.

    Internal Reference Count¶

    Object trong memory tồn tại chừng nào còn variable/property tham chiếu tới nó.

    • gán object vào variable khác -> tăng reference count
    • khi reference count về 0 -> IRIS có thể destroy object khỏi memory

    Điều này giải thích vì sao:

    • kill hết references rồi %OpenId() lại có thể load một instance mới
    • swizzled object biến mất khỏi memory khi không còn ai tham chiếu nữa

    Decision Table¶

    Need Better choice
    tạo instance mới để nhập data %New()
    tải row đã lưu %OpenId()
    bỏ local edits chưa save %Reload()
    pre-check object exists %ExistsId()
    enforce lifecycle business rules callbacks phù hợp
    điều hướng relationship khi cần rely on swizzling

    Key Points¶

    • ✅ %New() tạo object trong memory; %Save() mới persist
    • ✅ %OpenId() trả OREF hoặc ""
    • ✅ %Save() dùng SaveSet và save toàn bộ graph như một transaction
    • ✅ Callback lifecycle quan trọng gồm %OnValidateObject(), %OnBeforeSave(), %OnAfterSave(), %OnSaveFinally()
    • ✅ Swizzling = lazy loading của referenced persistent object
    • ⚠️ Trong cùng process, %OpenId() cùng ID thường trả cùng object instance đang ở memory
    • ⚠️ Swizzling tiện nhưng có thể tạo I/O bất ngờ trong loop lớn
    • 💡 Nếu cần "quay về trạng thái trên disk", nghĩ tới %Reload() thay vì open lại rồi mong có object mới

    🖥️ Terminal Snippets¶

    // --- Create and save ---
SET person = ##class(MyApp.Person).%New()
SET person.Name = "Alice"
SET sc = person.%Save()
WRITE $SYSTEM.Status.GetErrorText(sc), !

// --- Open and check existence ---
WRITE ##class(MyApp.Person).%ExistsId(1), !
SET person = ##class(MyApp.Person).%OpenId(1)

// --- Reload to discard unsaved in-memory changes ---
DO person.%Reload()
