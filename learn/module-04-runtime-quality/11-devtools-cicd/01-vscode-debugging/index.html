    VS Code & Debugging¶

    Exam Domain: T2 · Development Lifecycle — cấu hình workspace, server connection, và debugger workflow trong VS Code

    Overview¶

    VS Code là IDE chính thức. Với exam, trọng tâm là hiểu client-side vs server-side editing, cấu hình .vscode/settings.json, và cách attach debugger theo dõi tiến trình trên server.

    Trong thực tế, VS Code làm việc với IRIS qua ObjectScript extension và Source Code File REST API, vì vậy việc save, compile, và debug đều gắn với cấu hình workspace chứ không chỉ là editor UI.

    Workspace Configuration¶

    File .vscode/settings.json thường có hai phần chính:

    1. intersystems.servers — định nghĩa các server có thể kết nối
    2. objectscript.conn — chọn server/namespace đang active
    {
  "intersystems.servers": {
    "local": {
      "webServer": {
        "scheme": "http",
        "host": "localhost",
        "port": 52773
      },
      "username": "_SYSTEM",
      "password": "SYS",
      "ns": "USER",
      "active": true
    }
  },
  "objectscript.conn": {
    "server": "local",
    "ns": "USER",
    "active": true
  }
}

    Why This Structure Matters¶

    Key Purpose
    host / port trỏ tới Web Gateway / REST endpoint của IRIS
    username / password credential dùng cho extension
    ns namespace mặc định để mở và compile code
    server tên logical của server đang được objectscript.conn chọn
    active đánh dấu connection hoặc workspace config đang dùng

    Server-side vs Client-side Editing¶

    Mode Đặc điểm Khi phù hợp
    Server-side editing Mở/sửa source trực tiếp trên server IRIS debug nhanh, lab nhỏ, sửa gấp
    Client-side editing File nằm trong git workspace, extension sync lên IRIS khi save team workflow, CI/CD, code review

    Trong repo học này, client-side editing là mode nên ưu tiên vì:

    • dễ review bằng git
    • dễ export/import nhất quán
    • khớp với CI/CD và Docker workflow

    Gotcha

    Server-side editing tiện cho thử nhanh nhưng dễ làm code trên server lệch với repo nếu dùng kéo dài.

    Debugging Flow¶

    Debugger của VS Code cho ObjectScript thường đi theo flow:

    1. mở class/routine trong workspace
    2. đặt breakpoint
    3. chạy hoặc attach vào process IRIS
    4. step qua code, xem local variables, call stack, watch expressions

    launch.json¶

    Trong workspace lớn, file .vscode/launch.json giúp lưu cấu hình debug session thay vì cấu hình thủ công mỗi lần.

    {
  "version": "0.2.0",
  "configurations": [
    {
      "name": "ObjectScript Attach",
      "type": "objectscript",
      "request": "attach",
      "server": "local",
      "ns": "USER"
    }
  ]
}

    launch.json không thay thế settings.json; nó chỉ mô tả cách khởi chạy hoặc attach debug.

    Terminal Debugging — ZBREAK / BREAK¶

    Khi không có VS Code (ví dụ: debug trực tiếp trong Terminal hoặc SSH session), dùng ZBREAK và BREAK để set breakpoints trong ObjectScript code:

    // Set breakpoint tại label trong routine
ZBREAK "MyLabel^MyRoutine"

// Breakpoint với điều kiện
ZBREAK "MyLabel^MyRoutine":condition

// Xem call stack hiện tại
WRITE $STACK, !
WRITE $STACK(-1, "PLACE"), !   // caller location
WRITE $STACK(-1, "MCODE"), !   // source line

// $ESTACK — execution level (tương tự stack depth)
WRITE $ESTACK, !

    ZBREAK vs VS Code Debugger

    VS Code Debugger: tốt cho interactive development, step-through, watch variables. ZBREAK: tốt cho debugging trong production-like environment, scripted conditions, terminal-only access.

    Command Mô tả
    ZBREAK "label^routine" Set breakpoint tại location
    ZBREAK "label^routine":cond Conditional breakpoint
    BREAK Trigger breakpoint ngay lập tức
    $STACK Số levels trong call stack
    $STACK(-1,"PLACE") Location của frame trên stack

    Management Portal in the Dev Workflow¶

    VS Code là IDE chính, nhưng Management Portal vẫn là công cụ rất quan trọng khi debug hoặc kiểm tra hệ thống:

    Portal area Use
    Terminal chạy thử code nhanh trong namespace
    SQL tools test query và xem execution plan
    Classes / routines xem doc comment, compile status
    Security / web apps kiểm tra auth, web app mapping
    Interoperability tools xem production state, message trace

    Portal không thay thế git/VS Code, nhưng cực hữu ích để xác nhận runtime behavior.

    Profiling & Performance Analysis¶

    Khi code chạy chậm hoặc tốn bộ nhớ, bạn không thể chỉ dùng VS Code Debugger. Bạn cần dùng các công cụ Profiling của IRIS:

    • ^%PROFILE: Tiện ích dòng lệnh để đo lường performance của ObjectScript code (routine/class). Nó ghi nhận thời gian thực thi (Time) và số lượng lệnh (Line count/Global references) ở cấp độ từng dòng code.
    • SQL Execution Plans: Dùng Management Portal (System Explorer > SQL) để xem cách IRIS thực thi một câu query, từ đó quyết định có cần tạo thêm Index hay không.
    • Caché Monitor / ^pButtons: Dùng để phân tích hiệu suất hệ thống tổng thể (OS level, disk I/O, memory) thay vì từng dòng code cụ thể.

    Background Jobs and Debug Context¶

    Khi code dùng JOB, hãy nhớ:

    • process con có $ZCHILD
    • parent và child không share local variables
    • nếu debug flow async/background, cần biết process nào đang chạy logic thật
    • sau JOB, biến $TEST cho biết lời gọi JOB có thành công hay không
    JOB ##class(MyApp.Worker).RunBatch()
IF '$TEST {
    WRITE "Could not start background job", !
    QUIT
}
WRITE "Child PID: ", $ZCHILD, !

    Nếu cần chạy child job ở namespace cụ thể, có thể dùng parameterized JOB syntax thay vì giả định child luôn ở cùng namespace hiện tại.

    BatchFlag — Large Dataset Jobs¶

    Cho các background jobs xử lý lượng lớn dữ liệu, set BatchFlag để tối ưu behavior:

    // Trong background job process:
DO $SYSTEM.Process.SetBatchFlag(1)   // enable batch mode
// ... xử lý large dataset ...
DO $SYSTEM.Process.SetBatchFlag(0)   // restore

// Đọc giá trị hiện tại:
WRITE $SYSTEM.Process.BatchFlag(), !

    BatchFlag ảnh hưởng đến: - Behavior của lock conflicts (không prompt user) - Output handling (suppress terminal output) - Phù hợp với unattended background processing

    NFS không support làm IRIS volume

    Exam Trap: NFS (Network File System) không được support làm storage volume cho IRIS database files (.IRIS.DAT, WIJ, journal files). Luôn dùng local block storage hoặc SAN.

    Key Points¶

    • ✅ VS Code dùng ObjectScript extension + server configuration trong .vscode/settings.json
    • ✅ objectscript.conn chọn server và namespace active cho workspace hiện tại
    • ✅ launch.json giữ cấu hình attach/launch cho debugger
    • ✅ Client-side editing phù hợp hơn cho git và CI/CD
    • ✅ ZBREAK "label^routine" — set terminal breakpoints; ZBREAK "label":cond cho conditional
    • ✅ $SYSTEM.Process.SetBatchFlag(1) — optimize unattended large-data background jobs
    • ⚠️ Save trong VS Code thường sync ngay lên IRIS server — đừng giả định file local và file server là hai bản tách rời
    • ⚠️ Debug background code cần để ý process context và $ZCHILD
    • ⚠️ NFS không support làm IRIS storage volume — luôn dùng local block storage hoặc SAN
    • 💡 Management Portal vẫn là công cụ phụ trợ rất mạnh để kiểm tra runtime, SQL, security, và production state

    🖥 Terminal Snippets¶

    // --- Show current namespace ---
WRITE $NAMESPACE, !

// --- Spawn a background job and confirm it started ---
JOB ##class(MyApp.Worker).RunBatch()
WRITE "JOB success? ", $TEST, !
WRITE "Child PID: ", $ZCHILD, !

// --- Switch namespace before testing a class manually ---
ZNSPACE "USER"
DO ##class(MyApp.Utils).SmokeTest()
