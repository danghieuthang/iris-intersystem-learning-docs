    11 · Dev Tools, CI/CD & Source Control¶

    Exam Domain: T2 · Development Lifecycle — VS Code, debugging, monitoring tools, CI/CD pipelines, source control integration

    Overview¶

    Chu đề này bao gồm toàn bộ vòng đời phát triển trên nền tảng InterSystems IRIS: từ cấu hình VS Code và ObjectScript extension, profiling hiệu năng, chạy nền với lệnh JOB, đến đóng gói bằng Docker, quản lý cấu hình với CPF, và tích hợp source control. Đây là nền tảng để xây dựng CI/CD pipeline hiện đại cho ứng dụng IRIS.

    Development Tools¶

    VS Code + ObjectScript Extension¶

    VS Code là IDE chính thức được InterSystems khuyến nghị cho phát triển IRIS. Extension InterSystems ObjectScript kết nối trực tiếp đến IRIS instance qua cấu hình trong .vscode/settings.json.

    Cấu hình kết nối server: 

    {
  "intersystems.servers": {
    "local": {
      "webServer": {
        "scheme": "http",
        "host": "localhost",
        "port": 52773
      },
      "username": "_SYSTEM"
    }
  },
  "objectscript.conn": {
    "server": "local",
    "ns": "USER",
    "active": true
  }
}

    Hai chế độ làm việc:

    Chế độ Mô tả Khi nào dùng
    Server-side editing Mở và sửa file .cls trực tiếp trên server IRIS Thay đổi nhanh, không cần sync
    Client-side editing File lưu trên disk, extension tự đồng bộ lên server khi save Dùng với git, CI/CD

    Debugging: - Đặt breakpoint trực tiếp trong VS Code trên file .cls - Chạy debug bằng cách attach vào process IRIS đang chạy - Xem biến local, call stack trong giao diện Debug của VS Code

    Performance Profiling Tools¶

    IRIS cung cấp nhiều công cụ profiling chạy trực tiếp trong terminal, không cần cài thêm gì:

    Công cụ Mục đích Cách sử dụng
    ^%SYS.MONLBL Thống kê từng dòng code: số lần chạy, thời gian, số global ref DO ^%SYS.MONLBL → chạy code → xem report
    ^PROFILE Tìm hotspot trong routine/method DO ^PROFILE
    ^TRACE Trace thay đổi biến và lời gọi method DO ^TRACE
    ^SystemPerformance Thu thập metrics toàn hệ thống Chạy trong namespace %SYS
    ^PERFSAMPLE Lấy mẫu process tần suất cao Hiển thị các process đang làm gì

    Lưu ý: ^%SYS.MONLBL là công cụ đầu tiên cần nghĩ đến khi tìm dòng code gây chậm trong ObjectScript.

    Background Execution — JOB Command¶

    Lệnh JOB tạo một process con độc lập chạy nền, phù hợp cho các tác vụ tốn thời gian:

    // Spawn a background process
JOB ##class(MyApp.Worker).Process()

// Pass arguments to background job
JOB ##class(MyApp.Worker).ProcessBatch(100)

// Check child process PID
WRITE "Child PID: ", $ZCHILD, !
    • $ZCHILD: biến system chứa PID của process con vừa được tạo
    • Process con chạy độc lập — parent process không block để chờ
    • Dùng cho: batch processing, long-running import, async operations

    Code Documentation with ///¶

    IRIS hỗ trợ auto-documentation bằng cú pháp triple-slash ///. Tài liệu này có thể xem trong Management Portal → System Explorer → Classes.

    /// Finds a person by their name.
/// @param pName The name to search for
/// @return A Person object or "" if not found
ClassMethod FindByName(pName As %String) As MyApp.Person
{
    // implementation
}

/// Maximum number of retry attempts
Parameter MAXRETRIES = 3;

    Lưu ý: Phải dùng đúng /// (triple slash). Comment // thông thường không được đưa vào tài liệu.

    Docker Compose for IRIS¶

    Docker Compose là cách chuẩn để chạy IRIS trong môi trường phát triển và CI/CD. Hai port quan trọng cần biết:

    Port Dịch vụ Dùng cho
    52773 Web Gateway Management Portal, REST API, CSP
    1972 SuperServer JDBC, ODBC, Native API connections

    Cấu trúc docker-compose.yml cơ bản: 

    services:
  iris:
    image: intersystemsdc/iris-community:latest
    ports:
      - "52773:52773"   # Web access (Management Portal + REST)
      - "1972:1972"     # SuperServer (JDBC/ODBC/Native API)
    volumes:
      - ./src:/home/irisowner/dev  # Mount source code into container
    environment:
      - IRIS_PASSWORD=SYS
    healthcheck:
      test: ["CMD", "iris", "status"]
      interval: 10s
      timeout: 5s
      retries: 5

    Health check rất quan trọng trong CI/CD để các bước tiếp theo chỉ chạy sau khi IRIS đã sẵn sàng.

    CI/CD with IRIS¶

    Deployment Options¶

    IRIS hỗ trợ nhiều phương thức triển khai tùy theo môi trường:

    Phương thức Mô tả Khi nào dùng
    Docker containers Image intersystemsdc/iris-community; reproducible environment Modern CI/CD, cloud deployment
    IRIS Installer (^%INSTALLER) XML manifest cấu hình IRIS: tạo namespace, import code, set config Cài trên server vật lý/VM sẵn có
    IPM (ObjectScript Package Manager) zpm "install mypackage" — cài package như npm Chia sẻ thư viện, reusable components

    CPF File Management¶

    CPF (Configuration Parameter File) là file cấu hình chính của IRIS instance (tương tự /etc/myapp.conf). Trong CI/CD, MERGE command cho phép áp dụng cấu hình tăng dần (incremental) mà không ghi đè toàn bộ:

    ; merge.cpf — only adds/changes, never removes existing settings
[config]
globals=0,0,25,0,0,0

[Namespaces]
USER

    Áp dụng merge trong Dockerfile: 

    COPY merge.cpf /
RUN iris start IRIS && \
    iris session IRIS -U"%SYS" \
      "##class(Config.CPF).Upgrade()" && \
    iris stop IRIS quietly

    Có thể dùng REST API /api/monitor để thay đổi cấu hình programmatically.

    Source Control Integration¶

    git-source-control (by George James Software) là extension phổ biến nhất để tích hợp git với IRIS:

    • Hook vào các sự kiện của IRIS (compile, save, delete class)
    • Tự động export class ra filesystem khi có thay đổi
    • File được export theo cấu trúc thư mục phản ánh package name

    Lưu ý quan trọng khi import class đã thay đổi: - Nếu thay đổi cấu trúc persistent class (thêm/xóa property, đổi kiểu dữ liệu) → dữ liệu đã lưu có thể không tương thích - Giải pháp: dùng %Migration class hoặc viết migration script trước khi deploy

    %UnitTest in CI/CD¶

    // Run all tests in a package (recursive)
DO ##class(%UnitTest.Manager).RunTest("MyApp.Test", "/recursive")

// Run specific test class
DO ##class(%UnitTest.Manager).RunTest("MyApp.Test.PersonTest")
    • Kết quả lưu trong global ^UnitTestRoot — CI/CD pipeline có thể đọc để xác định pass/fail
    • Integration tests: test với external systems (DB, API) — nên chạy trong phase riêng
    • Load/stress testing: không dùng %UnitTest; dùng công cụ bên ngoài như k6, JMeter

    Promoting Changes Between Environments¶

    // Export a class to filesystem
DO $SYSTEM.OBJ.Export("MyApp.Person.cls", "C:\export\MyApp.Person.cls")

// Export multiple classes matching a pattern
DO $SYSTEM.OBJ.Export("MyApp.*.cls", "C:\export\MyApp.xml")

// Import and compile
DO $SYSTEM.OBJ.Load("C:\export\MyApp.Person.cls", "ck")

    Flags cho $SYSTEM.OBJ.Load():

    Flag Ý nghĩa
    c Compile sau khi load
    k Keep source (giữ lại source code)
    d No display (im lặng khi chạy)
    e Suppress errors

    Cảnh báo: Import class persistent đã thay đổi schema lên environment có dữ liệu thực → có thể gây lỗi storage incompatibility. Luôn test trước trên environment staging.

    Key Points¶

    • ✅ ^%SYS.MONLBL = line-level profiler; ^SystemPerformance = system-wide metrics collection
    • ✅ Lệnh JOB tạo background process; biến $ZCHILD chứa PID của process con vừa tạo
    • ✅ Port 1972 = SuperServer (JDBC/ODBC/Native API); Port 52773 = Web (Portal/REST/CSP)
    • ✅ CPF MERGE là additive — chỉ thêm/thay đổi setting, không xóa cấu hình đang có
    • ⚠️ Import persistent class có schema changes lên environment có dữ liệu → nguy cơ storage incompatibility
    • ⚠️ /// mới được đưa vào tài liệu API; comment // thông thường thì không
    • ⚠️ Health check trong Docker Compose là bắt buộc trong CI/CD — IRIS cần thời gian khởi động
    • 💡 Containers + CPF MERGE là approach hiện đại và được khuyến nghị cho CI/CD với IRIS
    • 💡 Luôn chạy %UnitTest suite trước khi promote code lên production

    🖥️ Terminal Snippets¶

    // --- Start line-level profiler ---
DO ^%SYS.MONLBL

// --- Run a background job ---
JOB ##class(MyApp.Worker).Process()
WRITE "Child PID: ", $ZCHILD, !

// --- Export class to filesystem ---
DO $SYSTEM.OBJ.Export("MyApp.Person.cls", "C:\export\MyApp.Person.cls")

// --- Import and compile class (c=compile, k=keep source) ---
DO $SYSTEM.OBJ.Load("C:\export\MyApp.Person.cls", "ck")

// --- Run all unit tests recursively ---
DO ##class(%UnitTest.Manager).RunTest("MyApp.Test", "/recursive")

// --- Check unit test results global ---
ZWRITE ^UnitTestRoot
